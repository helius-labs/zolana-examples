# Confidential Swap (Xark) -- Benchmark

Generated by `cargo test --release --manifest-path test/Cargo.toml --test bench_cu -- --ignored --nocapture`; do not edit.

Compute units come from replaying each instruction under mollusk with the profiling build of the example program (`profile-program`, light-program-profiler). Only the example program is profiled: `process_<ix>_ix` is the whole instruction, `verify_<ix>_proof` the program proof verification (public-input hashing and Groth16 verification), and the shielded-pool program is a plain build whose CPI cost is the `cpi_spp_transact*` row. The shielded-pool program differs between the gnark and Xark implementations, so `SPP CPI CU` is not an apples-to-apples comparison; `Verify CU` and the circuit columns are. Proving times are warm release-build medians of 5 runs after 1 warm-up run: the program circuit proof in process with its artifacts loaded before timing, the SPP proof against the running prover server with its keys loaded. Warm proving time, and the Summary's circuit proof, is one full call of the implementation's prove function. Per-proof setup is the part of that call that reloads circuit artifacts before proving starts, timed on its own. In-memory proving time is a proof with the constraint rows and the decoded proving key held in memory, which is what the two implementations' provers compare on. Warm minus in-memory proving time is the full per-proof overhead, the proving-key decode included; per-proof setup is only its part before proving starts, so the columns do not sum. Key load is the median of 5 cold loads of a circuit's proving artifacts, each in a fresh child process of the bench; the SPP prover's key load is not measured. For gnark it compiles the constraint system and reads the proving key, after which the prover is ready. For Xark it is a one-time checksum check and copy of the circuit bytecode and proving key, plus an expansion of the bytecode; it does not make the prover ready, and every proof still pays the per-proof setup and the proving-key decode. Xark 0.3.0's `Circuit::prove`, which the SDK proves with, keeps nothing in memory between proofs: every call re-reads `circuit.xbc`, rebuilds the reduced R1CS rows with `rows_for_key` (the SDK's checked circuit copy has no `r1cs.stream` cache), opens `pk.bin` with `SerializedPk::open` and decodes the key's points from the file while proving, and solves the witness. Per-proof setup times the first three steps; the key decode runs inside the proof, so only the in-memory proving time removes it. In-memory proving time proves through public Xark 0.3.0 APIs with the rows built and the whole proving key decoded once before timing (per proof: `resolve_input_ids`, `xark_ir::solver::solve_and_check`, then `xark_groth16::prove` on an `InMemoryPk`), and checks each proof against the key's verifying key; it is the Xark time that compares with gnark's warm proving time. Proof bytes are the serialized Groth16 proof points the instruction submits. Transaction sizes are those of the serialized v1 transaction carrying the instruction.
