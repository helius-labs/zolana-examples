# Timelock Escrow (Xark) -- Benchmark

Generated by `cargo test --release --manifest-path test/Cargo.toml --test bench_cu -- --ignored --nocapture`; do not edit.

Compute units come from replaying each instruction under mollusk with the profiling build of the example program (`profile-program`, light-program-profiler). Only the example program is profiled: `process_<ix>_ix` is the whole instruction, `verify_<ix>_proof` the program proof verification (public-input hashing and Groth16 verification), and the shielded-pool program is a plain build whose CPI cost is the `cpi_spp_transact*` row. The shielded-pool program differs between the gnark and Xark implementations, so `SPP CPI CU` is not an apples-to-apples comparison; `Verify CU` and the circuit columns are. Proving times are warm release-build medians of 5 proofs after 1 warm-up proof: the program circuit proof in process with its artifacts loaded before timing, the SPP proof against the running prover server with its keys loaded. Key load is the median of 5 cold loads of a circuit's proving artifacts into the in-process prover until it can prove (gnark: compile the constraint system and read the proving key; Xark: read the checksum-checked circuit bytecode and proving key), each in a fresh child process of the bench; the SPP prover's key load is not measured. The Xark prover streams the proving key from its file during each proof. Proof bytes are the serialized Groth16 proof points the instruction submits. Transaction sizes are those of the serialized v1 transaction carrying the instruction.
